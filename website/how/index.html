How it decides.

The AI reads the tender; these rules decide. Everything on this page was derived from the prototype’s decision code when the site was built: the rules were run on probe inputs and the weights and thresholds were read from the code and checked against those runs. If the code changes, this page changes with it.

Each requirement gets a status.

The AI extracts the hard requirements with a confidence. Before the typed rule runs, two things are checked: the AI’s confidence and whether the owner has answered the line.

  • Meets
    the profile satisfies the line
  • Risk
    not met, but a partner, a translation or a visit could cover it; it costs half the points
  • Needs your check
    the AI is unsure; only the owner can answer, and until then the line counts nothing
  • Fails
    a knock-out: the tender is No-go whatever the score

The fit score, 0 to 100.

Four parts, added up. The statuses above feed the third one.

The four parts of the fit score
PartPointsHow
Sector fit4040 if any of the tender’s CPV codes starts with one of the profile’s two-digit divisions, else 0 (and the tender is No-go).
Size fit2020 when the contract value lies between the profile’s minimum and maximum, 8 when it is smaller, 5 when it is larger.
Requirements3030 × (met + 0.5 × risk) ÷ the number of requirements, rounded. A line that needs the owner’s check counts 0.
Time to prepare1010 with 21+ days left, 5 with 10+ days left, 2 with 1+ days left, 0 on the deadline day.

everything else: a line needs the owner’s check, more than 1 risk, or a score under 70under 70, or higher with open lines

Probe: with otherwise identical inputs the code gives Maybe at 68 and Go at 70, so the Go line is 70. A knock-out caps the score at 25; a verdict is never shown by colour alone. Ranking in the feed: Go → Maybe → No-go → Closed, then by score, then by days left.

What is real in this prototype.

  • Needs your check

    Simulated: reading tenders, translating, answering questions and drafting the profile. Pre-written output after a short delay, labelled “Simulated AI” wherever it appears. No model is called and there are no keys. The simulated layer on GitHub.

  • Go

    Real: the decision rules on this page, deterministic and tested: 24 unit tests, 11 pinned demo numbers, a property test of 3,000 random cases per run and 209 browser checks. The decision code on GitHub.

  • No-go

    Fictional: every company, buyer, tender, page number and quote. None of it is interview evidence. The demo data on GitHub.

This page itself is generated: the script that probes the code writes it and the same content as a document, and the build fails if either falls behind the code.
